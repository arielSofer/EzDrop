# הרצת Kotlin מהדפדפן באמולטור Android

במצב לימוד → כתיבת קוד, הכפתור **הרץ ב־Android** בסרגל העליון, הכפתור בעורך ו־⌘R שולחים את קובצי Kotlin השמורים לשרת המקומי. השרת בונה APK, פותח את אמולטור הלמידה אם צריך, מתקין ומפעיל את המסך. המלווה מציג התקדמות ושגיאות; משימת ההרצה האחרונה עוברת רק לאחר בנייה, התקנה ואימות שהתהליך נשאר פעיל. יש לבדוק ידנית את התנהגות הקלט והכפתורים.

האמולטור מופיע בחלון Android נפרד במחשב. הוא אינו מוזרם לתוך הדפדפן. השרת המקומי חייב לפעול; אתר מרוחק לבדו אינו יכול להפעיל אמולטור במחשב התלמיד.

## כתיבת המסך

- קובצי התלמיד נמצאים ב־`app/src/main/java/.../*.kt`.
- בקובץ המסך נדרשת הצהרת `package`, ופונקציית `@Composable` ציבורית ששמה כשם הקובץ ללא `.kt`, כפי שמופיע במשימה. הפונקציה צריכה להיות ניתנת לקריאה ללא ארגומנטים.
- השלד הראשוני מכיל הוראות בלבד. התלמיד כותב את הפונקציה; עד אז ההרצה מחזירה שגיאה אמיתית.
- כל קובצי Kotlin של הפרויקט משתתפים בבנייה. קובצי Swift אינם נשלחים למנוע Android.
- תבנית השרת כוללת Compose Material3, Activity, Lifecycle ViewModel, Lifecycle Compose ו־Navigation Compose. הוספת ספריות או הרשאות Android נוספות מחייבת הרחבה מפורשת של תבנית הבנייה בשרת.
- השרת יוצר Activity מארח ותצורת Gradle. לוגיקת המסך והעיצוב מגיעים מקוד התלמיד.

## הסביבה המקומית שהוכנה

| רכיב | גרסה או מיקום |
| --- | --- |
| JDK | Homebrew `openjdk@17` |
| Android SDK | `~/Library/Android/sdk` |
| SDK command-line tools | `16.0` |
| Android platform / build tools | API 35 / `35.0.0` |
| תמונת מערכת | `system-images;android-35;google_apis;arm64-v8a` |
| AVD | `AgenticDesigner_API_35`, פרופיל Pixel 7 |
| Gradle | `8.11.1`, תחת `~/Library/Application Support/AgenticDesigner/AndroidTools` |
| Android Gradle Plugin | `8.9.2` |
| Kotlin / Compose compiler plugin | `2.1.20` |
| Compose BOM | `2025.04.01` |

גרסאות JDK, Gradle ו־SDK נבחרו לפי [טבלת התאימות הרשמית של AGP 8.9](https://developer.android.com/build/releases/agp-8-9-0-release-notes).

במחשב אחר יש להתקין JDK 17, [Android SDK command-line tools](https://developer.android.com/tools/sdkmanager), Gradle 8.11.1 ואת החבילות בטבלה. ניתן להשתמש ב־SDK מותקן של Android Studio. אחרי הגדרת `JAVA_HOME` ו־`ANDROID_HOME`, יצירת האמולטור ב־Apple Silicon נעשית באמצעות:

```sh
"$ANDROID_HOME/cmdline-tools/16.0/bin/sdkmanager" 'platform-tools' 'platforms;android-35' 'build-tools;35.0.0' 'emulator' 'system-images;android-35;google_apis;arm64-v8a'
"$ANDROID_HOME/cmdline-tools/16.0/bin/avdmanager" create avd -n AgenticDesigner_API_35 -k 'system-images;android-35;google_apis;arm64-v8a' -d pixel_7
```

נתיבים חלופיים ניתנים להגדרה בסביבת השרת באמצעות `ANDROID_HOME`, `AGENTIC_ANDROID_JAVA_HOME`, `AGENTIC_ANDROID_GRADLE` (הנתיב לקובץ ההפעלה של Gradle). ברירות המחדל והאימות הנוכחי מיועדים ל־macOS עם Apple Silicon.

## הפעלה ובדיקה

מתיקיית `agentic-designer-react`, מפעילים את השרת ואת יישום הדפדפן לפי הוראות הפרויקט. לבדיקת מנוע Android עם מסך דוגמה מבודד:

```sh
npx tsx scripts/verify-android-emulator.ts
```

הבדיקה יוצרת אפליקציה נפרדת עם טקסט בעברית ומונה לחיצות, ואינה עורכת את קוד התלמיד. יציאה עם קוד 0 מעידה על בנייה, התקנה והישארות תהליך האפליקציה פעיל לאחר ההפעלה.

## התנהגות ותפעול

- הבנייה הראשונה מורידה ספריות; בניות נוספות משתמשות במטמון Gradle. אין קריאות למודל AI בזמן בנייה או הרצה.
- הבנייה מתבצעת בתיקייה ייעודית לפי hash של מזהה הפרויקט תחת `AndroidProjects`. רק מקורות שהשרת מנהל מוחלפים; מטמוני הבנייה נשמרים.
- רק אמולטור ששמו `AgenticDesigner_API_35` מקבל התקנות. טלפונים מחוברים ואמולטורים אחרים אינם יעדי ההרצה.
- רק הרצה אחת בכל פעם בשרת. לחיצות כפולות בדפדפן נבלמות.
- כישלון בבנייה מונע התקנת APK ישן. כישלון התקנה או קריסה לאחר הפעלה אינם מדווחים כהצלחה.
- שינוי מקור או החלפת פרויקט בזמן בנייה מסמנים את התוצאה כלא עדכנית. אין אישור אוטומטי לגרסה החדשה.
- שגיאות קומפיילר מוצגות עם קובץ ושורה, ופלט הבנייה זמין לפתיחה בעורך ולמלווה.
- זהו מנוע פיתוח מקומי למשתמש יחיד. שירות ענן שמקבל קוד מתלמידים רבים דורש בידוד בנייה והרצה נפרד לכל משתמש.

## מעבר בין מסכי הלימוד

בחירת מסך בלשוניות **עיצוב היעד** בוחרת גם את קובץ Kotlin ואת משימות המלווה שלו. בפעם הראשונה נוצר עבורו שלד נפרד; בביקורים הבאים נשמרים הקוד והצעד האחרון. גם בחירת קובץ מסך מוכר ברשימת הקבצים מסנכרנת את המלווה. הבחירה וההתקדמות נשמרות לאחר רענון. איפוס שלד חל רק על המסך הפעיל.

ההרצה העליונה מפעילה את המסך הפעיל במלווה; כפתור ההרצה בעורך מפעיל את הקובץ הנבחר. לאחר השלמת משימת ההרצה אפשר להמשיך לכתיבת המסך הבא. מעבר בין מסכים בסביבת הלימוד אינו מייצר אוטומטית ניווט בתוך אפליקציית Android — את הניווט התלמיד עדיין כותב בקוד.

## אשף ההתקנה המקומית

כפתור **הכנת Android** בסרגל פותח אשף בעברית. ניסיון הרצה בודק מראש את הסביבה ופותח את האשף כשחסרים כלים או כשהתקנה עדיין רצה. האשף מזהה Java 17, Gradle, כלי SDK, תמונת מערכת והמכשיר הווירטואלי. אפשר לפתוח ממנו מסך בדיקה נפרד עם כפתור ומונה, בלי לערוך את פרויקט התלמיד.

ההתקנה האוטומטית נתמכת כרגע ב־macOS עם Apple Silicon בלבד. היא דורשת לפחות 12 GB פנויים, אינטרנט והסכמה לתנאי ההתקנה. היא משתמשת ב־SDK וב־Java שכבר זמינים בנתיבים המוגדרים. אם Java חסר, Temurin 17 יורד לתיקיית הכלים הפרטית של המערכת, בלי Homebrew ובלי הרשאות מנהל. Gradle וכלי SDK יורדים מארכיונים רשמיים עם אימות checksum; sdkmanager מתקין את חבילות Android הנדרשות ומכשיר Pixel 7 ייעודי נוצר ללא דריסת AVD קיים.

ההתקנה מתנהלת בשרת המקומי, כך שסגירת החלון ורענון הדפדפן אינם עוצרים אותה. אחרי ניתוק אפשר לפתוח שוב ולבדוק מצב. כיבוי השרת אינו נתמך כהשהיית התקנה. תקלה מוצגת באשף, והרכיבים שכבר הותקנו נבדקים מחדש בניסיון הבא. הגדרות נתיב שגויות או תיקיות קיימות פגומות אינן נדרסות אוטומטית.

בדיקת התקנה אמיתית בסביבת SDK מבודדת (מורידה כמה GB, ומשאירה תיקיית בדיקה זמנית שעל הנתיב שלה הסקריפט מדווח):

```sh
npx tsx scripts/verify-android-setup.ts
```

מקורות ההתקנה: [Android SDK manager](https://developer.android.com/tools/sdkmanager), [Adoptium API](https://api.adoptium.net/q/swagger-ui/), [Gradle distributions](https://services.gradle.org/distributions/).

מסך ריק אחרי הרצה מוצלחת יכול להיות תוצאה תקינה: `Column` ללא רכיבים אינו מציג תוכן. הודעת ההרצה והמלווה מבהירים שבנייה והפעלת תהליך אינן אישור להשלמת העיצוב. לדוגמה, `Text("שלום, Android!")` בתוך הפריסה יוסיף תוכן גלוי.

בפאנל התצוגה אפשר לעבור בין **עיצוב היעד** לבין **Preview מהקוד**. ה־Preview המהיר מפענח מקומית רכיבי Compose בסיסיים ומתעדכן כ־180 מילישניות לאחר ההקלדה, ללא Build וללא API. הוא תומך בפריסות, טקסט, שדות, כפתורים, רווחים וערכי מצב מקומיים. אפשר להקליד בשדות וללחוץ על כפתורים: onValueChange ו־onClick תומכים בהשמות, חיבור מחרוזות, מונה, החלפת boolean וביטויי enabled פשוטים. אין הרצת Kotlin מלאה. פעולה לא נתמכת מציגה הסבר ואינה משנה חלקית את המצב. איפוס התצוגה או שינוי קוד מחזירים לערכים הראשוניים. קוד שאינו נתמך מסומן. בזמן סוגריים לא מאוזנים נשמרת התצוגה האחרונה עם הודעה. בדיקת קומפילציה, חיישנים, אינטראקציות ועיצוב Android המדויק נעשית דרך הרץ ב־Android. שירות ההרצה עדיין יכול להחזיר צילום אמיתי, אך הוא אינו מקור התצוגה המהירה.

לפני הוראות הכתיבה בכל אחת מחמש משימות Kotlin מופיע הסבר מקומי על הרכיב, הפרמטרים שלו, imports, מיקום הקוד, דוגמאות וטעויות נפוצות. אפשר לבחור הסבר של משימה אחרת בלי לשנות את ההתקדמות. ההסברים האלה אינם משתמשים ב־API.

בדיקת בנייה והרצה של דוגמאות ההדרכה עצמן, כולל צילום Preview בפרויקט בדיקה נפרד:

```sh
npx tsx scripts/verify-kotlin-lessons.ts
```


המלווה כולל כרטיסי ״מעצבים כמו המקור״ לפי כל רכיב בעיצוב השמור: צבעי רקע וטקסט, גודל ומשקל גופן, יישור, מידות, מיקום, רדיוס פינות ורווח מהרכיב הקודם. הדוגמאות משתמשות בערכי המסך ולא בצבעי Material כלליים. משימות הטקסט, השדות והכפתורים מכסות את כל הרכיבים מסוג זה; אם אין שדות או כפתורים לא מבקשים להמציא אותם. מידות המקור הן בסיס ללמידה; יש להתאים פריסה רספונסיבית, גופנים ושוליים בטוחים באמולטור.

Snapshot בגרסה 2 שומר גאומטריה וסגנון. בפרויקטים ישנים מושלמים הנתונים החסרים לפי מזהי הרכיבים בעיצוב הקיים, תוך שימור הטקסט והצבעים שכבר הוקפאו. אם העיצוב השתנה מאז והנתון לא נשמר בעבר, אין שחזור ודאי של ערכו המקורי. קוד התלמיד והשלב הפעיל נשמרים.

ביטול ושחזור בעורך פונים ישירות להיסטוריית מודל Monaco, עם טיפול מוקדם בקיצורי Cmd/Ctrl Z וב־beforeinput של פעולות Safari. בוצע אימות ידני בעורך אמיתי ב־Safari: הוספת טקסט, Cmd Z והחזרתו ב־Cmd Shift Z, בקובץ בדיקה נפרד מהפרויקט.


ליווי הכתיבה מוצג כעת בצעדים קטנים לכל מסך: שלד, רקע, שוליים ואז תוכן, צבע, גופן, פינות וריווח של רכיב אחד בכל פעם. אין קוד פתרון גלוי בהתחלה. הרמזים נפתחים ברצף: הסבר נוסף, רמז תחביר, דוגמה קטנה ורק בלחיצה מפורשת פתרון לצעד הנוכחי. המעבר דורש בדיקה מקומית של המאפיין כשנתמך, אישור השוואה חזותית והסבר של לפחות ארבע מילים. זה אינו ציון סמנטי אוטומטי לתשובה. צעדי פריסה מורכבת נשענים על בדיקה עצמית/מורה ומסומנים ככאלה.

הצעד ורשימת הצעדים שהושלמו נשמרים בנפרד ב־localStorage לפי מזהה הפרויקט והמסך. ההתקדמות הישנה וקוד התלמיד אינם נדרסים. בפרויקט קיים מתחילים בבדיקת השלד הקיים, ולא בכתיבה מחדש. סיום המסך דורש הרצת Android מוצלחת של גרסת הקוד הנוכחית.


עדכון קצב הלימוד: הצעדים הקטנים מאוגדים למשימות לפי תוצאה — שלד/רקע/שוליים יחד, ולאחר מכן רכיב שלם בכל משימה עם התוכן והעיצוב שלו. נבדקות כל דרישות החברים בקבוצה. מזהי הצעדים הקודמים נשמרים וממופים למשימה החדשה בלי איפוס ההתקדמות. לכל משימה שאלת תרחיש אחת (טקסט ארוך, פוקוס, נגישות או משוב), ותשובה כתובה היא רשות; אין עוד חסימת מעבר לפי ספירת מילים. קטעי הקוד והפקדים מוגבלים לרוחב הכרטיס ונשברים לפי הצורך.


משימות Icon כוללות כעת הוראות ביצוע גלויות: imports, מיקום הקריאה בפריסה, imageVector, contentDescription, tint ומידות. הפתרון המלא נשאר לפי בקשה. snapshot בגרסה 3 משמר גם iconName; כששם הסמל אינו ממופה, מוצג במפורש שסמל HelpOutline הוא זמני ולא שחזור המקור. סמלי Material ב־Android והדמייתם בדפדפן אינם זהים בהכרח לסמלי Apple המקוריים. מנוע Android כולל material-icons-extended. בכל המשימות מוצגים גם ההסבר והוראות הביצוע של תתי־המשימות, ולא רק תיאור העיצוב.
